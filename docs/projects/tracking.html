전화 클릭 전환 중복 차단

GA4 / GTM

기존 코드와 GTM의 전환 전송 경로를 확인하고, AI를 활용해 중복 차단을 실행·검토한 사례.

AI를 통한 실행 · 본인 검토
SCOPE

전화 클릭의 기존 전환 전송을 차단하는 작업을 AI로 실행하고 검토했습니다. 단독 코딩 사례나 실제 상담 성과로 표현하지 않습니다.

KEY DECISION

신규 전환 이벤트 번호만 바꿔서는 기존 전송이 사라지지 않으므로, 중복을 만드는 기존 호출 경로를 차단했습니다.

IN THIS CASE

01 Overview02 Problem03 Goal04 My Role05 Analysis06 Action07 Result08 Insight
01

Overview

랜딩페이지의 전화 클릭에 기존 전환 코드와 GTM 전환이 함께 작동하는 구조를 다룬 사례입니다.

02

Problem

전화 클릭 시 기존 wcs.cnv 호출이 남아 있으면 GTM의 신규 전환과 별도로 전송될 수 있었습니다. 이벤트 번호 변경만으로는 기존 경로를 제거할 수 없는 구조였습니다.

03

Goal

전화 클릭 기록을 유지하면서 해당 페이지의 기존 중복 전환 전송을 차단하는 것이 목표였습니다.

04

My Role

AI를 통해 전환 중복 차단 작업을 실행하고 수정 내용을 검토했습니다. 코드 구현을 혼자 직접 작성한 것으로 표현하지 않고, AI 활용과 본인의 검토 역할을 구분합니다.

05

Analysis

수정 전후 코드에서 기존 wcs.cnv 및 wcs_do 전송 경로와 phone_click 이벤트를 구분했습니다. 적용 범위를 특정 페이지와 전화 클릭으로 제한하는 조건을 검토했습니다.

06

Action

기존 전환 전송을 차단하고 phone_click DataLayer 이벤트를 유지하는 수정을 AI로 실행·검토했습니다. 보관된 GTM 스크립트에서 페이지 한정 차단 코드를 확인할 수 있습니다.

07

Result

수정 전후 코드 차이와 GTM 저장 스크립트가 남아 있습니다. 이 산출물은 중복 전송 경로 차단을 설명하는 근거이며, 실제 연결 통화나 상담 증가의 증거는 아닙니다.

08

Insight

전환 이름이나 번호보다 전송 경로를 확인해야 합니다. AI가 만든 수정도 적용 범위와 유지해야 할 이벤트를 기준으로 검토해야 합니다.

사례 확인 상태

역할: 본인 확인. 근거: 수정 전후 코드 차이와 GTM 저장 스크립트. 현재 라이브 상태와 실제 상담 성과는 이 사례에서 재검증하지 않았습니다.
